# SPEC: Polish findings and the ACP text separator from the 2026-11-21 A-Z e2e run

## Summary

This feature fixes the findings from the 2026-11-21 A-Z e2e run that no earlier bundle took, plus the one that waits on a dependency bump. The findings report is `projects/koda/e2e-2026-11-21/koda-wk-a-z-e2e-findings-2026-11-21.md` in the workspace repo.

- F16: ACP assistant text runs around a tool call are glued together ("...exports and throws.src/math.ts exports add..."). The fix shipped in `@nathapp/nax-agent-acp` 0.92.12 (nax #3011, PR #3015). The runner still pins 0.92.0.
- F11 (remainder): the fleet dashboard tables, the home "Needs you" list and the job logs page print a thread job's raw `thread-<id>` feature instead of the thread title.
- F21: the header shows the notifications bell next to an icon-only bell-ring / bell-off button, which turns browser pop-ups for approvals on and off. It reads as a second bell.
- F22: toasts open top-right, over the header's email, Account and Logout links.
- F27: the login tagline still says "Dev Ticket Tracker", and `/forgot-password` has no way back to sign in.
- F26: the dispatch form lists every runner profile as a flat row of chips (64 on koda-wk), with no filter or grouping. Its cost hint says "Test runs typically cost $1-2" beside a default cap of $5. The ticket picker stops at 8 suggestions with no sign that more match.
- F28: at 1440 px the board's Closed and Rejected columns are off-screen with no hint. A ticket card's closed-PR chip reads "Closed" with a red dot, as if the ticket were closed.
- F29: the analytics charts log the Unovis warning "Crosshair: Y accessors have not been configured" (two per page).
- F19 (remainder): axe reports `label` and `select-name` on both new-thread forms, and `scrollable-region-focusable` on the approval policies table.

## Motivation

These are the last open findings of the A-Z run. Each is small, but together they make the app look unfinished:

- glued agent text;
- raw ids;
- a header icon nobody can name;
- toasts that cover the sign-out link;
- a misleading cost hint and PR chip;
- console noise;
- form controls a screen reader cannot name.

### Failure Handling

| Case | Behaviour |
|---|---|
| A dashboard or home job whose thread was deleted (`threadId` set null) | `threadTitle` is `null`, and the web shows `t('fleet.jobs.threadFeature')`. |
| The browser has no `Notification` API | The settings section shows `notifications.browser.unsupported` and no checkbox. |
| The user enables browser notifications and the browser refuses permission | `enabled` stays false, and the section shows `notifications.browser.denied`. |
| `localStorage` throws | The preference holds for this tab only, as today. |

## Out of Scope

- Checking a password reset link when `/reset-password/<token>` opens (F27): it would need an API route that validates a token without consuming it, which lets anyone probe tokens. The submit-time check stays.
- Profile descriptions in the dispatch form (F26): a profile is only a name string in the runner's capabilities and the API's `RunnerSummaryDto.profiles`. Grouping by name prefix is the only structure used.
- Grouping or filtering on the label fields of the dispatch and schedule forms: only the filter applies there, with no `group-by-prefix`.
- Labelling every `FormLabel` / `FormControl` app-wide (for example by adding an id provide to `FormItem`): only the two new-thread forms are paired. Their backend picker (`fleet.threads.new.backend`) is not changed.
- Making every shared `Table` focusable: only `ApprovalPolicyList` passes `regionLabel`.
- The thread system note "memory:<id> saved" (stored English text in `ChatMessage.content`) and the fleet attention list's `subjectName`: these keep their text.
- `DashboardActiveJob` / `DashboardRecentJob` requester names: only `threadTitle` is added.
- Deleting the unused `components/ui/sonner/Toaster.vue` and its `index.ts` re-export.
- Removing the i18n keys `fleet.approvals.notifications.enable` and `fleet.approvals.notifications.disable`, which have no users once the header toggle goes: they stay in both locale files.
- Widening the `command` enum documented on `DashboardActiveJobDto`, `DashboardRecentJobDto` and `HomeJobDto` (today `['RUN', 'PLAN']`, although THREAD jobs flow through them): the regenerated `openapi.json` diff carries only the new `threadTitle` fields.
- Ticket picker matches beyond the one page of 100 tickets `TicketPicker.vue` loads (`OPTION_PAGE_SIZE`): "N more match" counts within that page, and typing does not fetch older tickets. A typed ref still works as today.
- `inheritAttrs` on `components/ui/table/Table.vue`: attributes keep falling through to both the wrapper and the `<table>` as today.
- Moving the header or rearranging other header controls: only the approval notification toggle leaves the header.
- Any runner code change beyond what the 0.92.15 types force: the bump is a dependency change, verified by the runner's typecheck and tests.
- Updating `.nax/mono/apps/runner/context.md`, which still says nax-agent is pinned to 0.91.6: `.nax/` is read-only to the run, so it is a manual edit after merge.
- Restarting the runner after deploy (`sudo launchctl kickstart -k system/dev.koda.runner`) and checking the deployed pages in a real browser on koda-wk: post-deploy manual steps, not stories.

### US-001: Runner picks up the ACP text-run separator

No dependencies. Workdir: `apps/runner`.

Bump `@nathapp/nax-agent` and `@nathapp/nax-agent-acp` in `apps/runner/package.json` to exact `0.92.15`, and run `bun install` from the repo root so that `bun.lock` matches. Fix only what the new types force in runner code.

Add a fake ACP agent fixture: a Bun script speaking newline-delimited JSON-RPC 2.0 over stdio.
- It answers `initialize` and `session/new`.
- On `session/prompt`, it sends the `session/update` notifications its scenario names, then answers `{ stopReason: "end_turn" }`. The scenario is chosen by an environment variable passed through `acpBackend`'s `env`.
- It ignores `session/cancel` (a notification needs no reply), answers any other request with a JSON-RPC "method not found" error, and exits when its stdin closes.

Add a real-process test (no database, not gated on `KODA_DB_TESTS`) that:
- opens an `AgentSession` through `createAgentSession({ backend, profile: 'ask', workdir, tools: [], transcriptStore: createMemoryTranscriptStore() })`, the same options the runner's ACP probe passes (`apps/runner/src/capabilities/acp-agent-probe.ts:140-142`). - iterates `session.send(<prompt>)` to its last event, which is `turn_end`, and reads that event's `output` (the final round's text, `TurnResult.output`);
- closes the session.
