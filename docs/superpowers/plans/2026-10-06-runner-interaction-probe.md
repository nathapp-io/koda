# Runner Interaction-Plugin Probe (#207, koda side) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A runner whose nax interaction plugin cannot initialise reports it in its capabilities, placement keeps jobs that would use that config off it (misfit `interaction`), the post-checkout job check refuses such a job before nax spawns, and the admin dashboard names the cause.

**Architecture:** nax will add an `interaction` result to `nax config --json` (spec §1, a separate nax PR, not in this plan). The runner reads it for the base config and each machine profile, carries it as a new optional `InteractionCheck` on `RunnerCapabilities` and `ProfileNeeds`, and refuses a job whose resolved chain fails. The API validates the field, adds a non-permanent misfit `interaction`, and a dashboard `runner_unhealthy` condition. Every field is optional: absent means unknown, never a misfit, so this PR is safe to merge and deploy before the nax release.

**Tech Stack:** Bun + TypeScript (runner, `bun:test`), NestJS 11 + Jest (api), Nuxt 3 + Jest (web), Commander + Jest (cli), shared `packages/fleet-protocol` types.

**Spec:** `docs/superpowers/specs/2026-10-06-runner-interaction-probe-design.md` (read it first; §1 is the nax contract this plan consumes, §2-§5 are what this plan builds).

## Global Constraints

- Branch: `fix/207-interaction-probe` (already exists locally with the spec commit `131e9f6a`). Never switch branches; never push or open a PR without the user's explicit approval.
- `FLEET_PROTOCOL_VERSION` stays `3` (spec §2). No Prisma/schema change.
- `InteractionCheck` wire shape is exactly `{ ok: boolean; plugin: string | null; code?: string }` — no `message` on the wire (spec §2).
- Server limits: `plugin` is `null` or a string of 1-64 chars; `code` matches `^[A-Z0-9_]{1,64}$`; unknown keys inside `interaction` reject the whole report (spec §4.1).
- Misfit `interaction` is NOT in `PERMANENT_MISFITS` (spec §4.2).
- Absent field (older nax, older runner) = unknown = never a misfit, never a condition (spec success criterion 7).
- Job-check refusal text: `capability mismatch: interaction <plugin> (<code>)`; `<plugin>` is `unknown` when null (spec §3.3).
- Probe warnings: `interaction <plugin> failed for the base config: <code>` and `interaction <plugin> failed for profile <name>: <code>`, each followed by ` (<sanitized nax message>)` when nax gave one (spec §3.2).
- Dashboard: at most 5 `interaction` conditions per runner, base config first, then profiles sorted by code unit (spec §4.3).
- i18n: API and web are separate systems; web strings go in `apps/web/i18n/locales/{en,zh}.json`, both languages, enforced by `tests/i18n/fleet-locale-parity.spec.ts`. The API sends no prose.
- Never hand-edit `apps/cli/src/generated/` (git-ignored, regenerated by `bun run generate`); `openapi.json` is committed.
- Repo lint forbids non-null assertions (`!`) in tests too; use explicit guards or `as` with a reason.
- No emojis; no `console.log`.

## Review Focus

1. **A malformed or future `interaction` document from nax** (status `"degraded"`, numeric plugin, lowercase code) must read as unknown or be coerced to a valid code, never make every profile look broken and never produce a report the server rejects (which would disable placement for the runner). Pinned in Task 6 (`parseInteraction` table).
2. **A failed status whose code nax left out or that does not match `^[A-Z0-9_]{1,64}$`** must still reach the server as `INTERACTION_INIT_FAILED`, not be dropped (an `ok:false` without a valid code would fail validation). Pinned in Task 6.
3. **A job that names profiles while the base config is broken** must still be placed when those profiles are fine (nax's base config is overlaid by the profile's own result). Pinned in Task 2.
4. **Probe ordering under `Promise.all`**: the base resolve and the per-profile resolves race, so tests must not assert on the order of `config` calls between them. Pinned in Task 7 (existing assertions filtered by `--profile`).
5. **Project-scope dashboard** must not leak plugin names or codes to project users; an `interaction` condition collapses to `configuration`. Pinned in Task 3.

```ts
/** #207, plan D271 style: strict, since a report the API accepts is what placement trusts. */
function parseInteraction(v: unknown, where: string): InteractionCheck {
  if (!isObj(v) || Object.keys(v).some((k) => !INTERACTION_KEYS.has(k)) || !isBool(v.ok)) fail(where);
  const check = v as Obj;
  const plugin = check.plugin;
  if (!(plugin === null || (typeof plugin === 'string' && plugin.length > 0 && plugin.length <= MAX_PLUGIN_NAME))) fail(where);
  if (check.code !== undefined && !(typeof check.code === 'string' && INTERACTION_CODE_RE.test(check.code))) fail(where);
  return { ok: check.ok as boolean, plugin: plugin as string | null, ...(check.code !== undefined ? { code: check.code as string } : {}) };
}
```

Add after `credentialConditions`:

```ts
/** #207 spec §4.3: base config first, then profiles by code unit; a runner with many broken profiles almost always has one broken base. */
export const MAX_INTERACTION_CONDITIONS = 5;

const byCodeUnit = (a: string, b: string): number => (a < b ? -1 : a > b ? 1 : 0);

const interactionCondition = (check: InteractionCheck, profile?: string): RunnerCondition => ({
  type: 'interaction',
  ...(check.plugin !== null ? { plugin: check.plugin } : {}),
  ...(check.code !== undefined ? { code: check.code } : {}),
  ...(profile !== undefined ? { profile } : {}),
});

function interactionConditions(caps: RunnerCapabilities): RunnerCondition[] {
  const base = caps.interaction?.ok === false ? [interactionCondition(caps.interaction)] : [];
  const profiles = Object.entries(caps.profiles)
```

```ts
const INTERACTION_STATUS: ReadonlySet<string> = new Set(['ok', 'failed', 'skipped']);
/** The server validator's bounds (apps/api/src/fleet/common/capabilities-core.ts `parseInteraction`). */
const INTERACTION_CODE = /^[A-Z0-9_]{1,64}$/;
const MAX_PLUGIN_NAME = 64;
const MAX_INTERACTION_MESSAGE = 300;
const INIT_FAILED = 'INTERACTION_INIT_FAILED';

export interface Interaction {
  readonly check: InteractionCheck;
  /** nax's redacted message for a failure: logged locally, never sent to the server (#207 spec §2). */
  readonly message: string | null;
}

/**
 * `ConfigJsonReport.interaction` (#207 spec §1). undefined: absent or not the documented shape, i.e. unknown — a
 * future nax must not make every profile look broken. A failure always carries a code the server accepts.
 */
export function parseInteraction(report: Obj): Interaction | undefined {
  const v = report['interaction'];
  if (!isObj(v)) return undefined;
  const { plugin, status, code, message } = v;
  if (typeof status !== 'string' || !INTERACTION_STATUS.has(status)) return undefined;
  const name = plugin === null ? null : typeof plugin === 'string' && plugin.length > 0 && plugin.length <= MAX_PLUGIN_NAME ? plugin : undefined;
  if (name === undefined) return undefined;
  if (status !== 'failed') return { check: { ok: true, plugin: name }, message: null };
  return {
    check: { ok: false, plugin: name, code: typeof code === 'string' && INTERACTION_CODE.test(code) ? code : INIT_FAILED },
    message: typeof message === 'string' && message !== '' ? message.slice(0, MAX_INTERACTION_MESSAGE) : null,
  };
}

/** #207 spec §3.3: the job check's refusal, after `capability mismatch: `. */
export const interactionReason = (check: InteractionCheck): string => `interaction ${check.plugin ?? 'unknown'} (${check.code ?? INIT_FAILED})`;
```
