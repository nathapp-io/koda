# Koda Web UI/UX Audit — 2026-11

Live audit of koda-wk (`:8030`, deployed `72c30222`) with real data, at 1440 px and 390 px, plus Lighthouse
snapshots. Fixes land as slices in [`MASTER-PLAN.md`](./MASTER-PLAN.md) (Status table + Decisions log); this
file tracks every finding until it is fixed or ruled out.

Status values: **Fixed** (on a branch, with the branch name), **Open**, **Needs decision**, **Won't fix** (with the reason).
Severity: **High** = wrong or broken information, accessibility failure; **Medium** = confusing or inconsistent;
**Low** = polish.

## Live check — 2026-11-12, koda-wk `b7d05eb5` then `6be516c1` (#446, #447, #448)

- R2-15: cause was permission-gated immediate watchers: the server rendered the content branch (no load had
  started) and the client the loading branch. #447 keeps the loading state until the first load settles on the
  admin and project approval-policy pages and the provider keys card. No hydration warning on any of the three
  pages at 390 px or 1440 px.
- R2-20: three causes. Each permissions composable instance fetched on its own (3 to 8 SSR reads of
  `/me/permissions` per page), the Nuxt auth routes shared one rate-limit bucket for every user (#444), and a
  client on a trusted private network could choose its bucket (#445). #446 fixed the client identity, #447
  (`dedupe: 'defer'`) cut the reads to 2 to 4, and #448 (payload-cached initial fetch) to exactly one per scope
  per render. `/me/notifications` is one read per full load and was not a cause on its own.
